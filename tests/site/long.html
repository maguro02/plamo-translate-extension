Postmortem: tenant cache leak

This short paragraph is used to load the model.

The root cause is that the cache key only includes the user ID, not the tenant ID. When the same user belongs to two tenants, the second request reads the first tenant's cached permissions, which is why the dashboard briefly shows projects the user should not see. I changed buildCacheKey() to include the tenant ID and added a regression test that logs in to two tenants in sequence. The fix is backward compatible, so old cache entries are simply rebuilt on the next request and no migration is needed.
